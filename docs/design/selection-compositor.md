# 帯のCPU合成と丸め

帯は6枚をsource-overで重ね、輝度を区間へ写してからL4へ丸める。
輝度はRGBの線形結合なので、各色の輝度を先に求めて同じ順で合成できる。
画素ごとのdouble演算を減らすため、標本と合成は整数で計算し、
L4の丸め境界に近い画素だけ従来のRGBの式で計算し直す。
位相は150、実画素は182×11、画像は256×16のまま保つ。

## 誤差を丸めに持ち込まない条件

座標は元画像の画素単位でQ28へ丸める。16画素周期がuint32の一周と一致する。
原点・xの増分・yの増分をそれぞれ一度だけ丸め、画素ごとに足し直すため累積加算はしない。
右下までの座標の差は `(1 + 181 + 10) / (2 × 2²⁸) = 96 / 2²⁸` 以下。
計算の余裕として97を使う。負の座標もunsignedの巡回で同じ周期に入る。

標本の小数部はQ22で切り捨てる。0〜1の画像の双線形補間は、
x・yそれぞれの変化に対して最大1の傾きを持つ。
座標と標本位置による1層の差は、正規化した輝度で
`2 × (97 / 2²⁸ + 1 / 2²²)` 以下になる。
2方向の補間結果をQ24へ切り捨てる差も合わせ、1標本の差はQ24で22未満と見積もる。
先に行う補間は8bit値×Q22なので、途中値は符号付き32bitへ収まる。
次の補間の積は符号付き64bitへ収まり、Q24へ写した値もuint32へ収まる。

色と不透明度のQ24への丸めは各0.5以下、不透明度との積とsource-overの
切り捨ては各1未満。0〜1の範囲のsource-overは直前の誤差を増幅しない。
下地1層と上の5層を合わせた差に余裕を置き、輝度で `192 / 2²⁴` を使う。
この見積もりは現在の固定したUV・182×11・6層の設計を対象にする。
doubleの座標式をアフィンの基底へ整理する差も、この余裕内として実入力の全位相で照合する。

輝度の範囲0.62〜1.0をL4へ写した差は
`192 / 2²⁴ × 15 / 0.38 < 1 / 2048`。
近似値から最も近い丸め境界までが1/2048を超えれば、同じL4値へ丸まる。
それ以内なら近似値を使わず、元の `Sample` と同じ小数位置・RGB合成・演算順序で
最終値を求める。黒白の端とclampも同じ扱いになる。
寸法と誤差の写像はコンパイル時にも検査する。

## 導入時に150コマを持つ

この合成は毎フレーム行わない。導入時に150位相を一度ずつ合成し、182×11の実画素だけを
GPUのMorton順のまま取り出して、150コマ（150,150バイト）をプラグインの静的領域に持つ。
1コマは連続する96本の範囲の合計1,001バイトで、位置はコンパイル時に決まる。
幅が偶数なので、端のニブルを混ぜ直す必要はない。余白（182×11の外）は全位相で0なので保存せず、
面は導入時に位相0のコマで初期化したまま余白を書き換えない。
毎フレームはその時のコマを96本の範囲として、使える面へコピーして面ごと排出するだけで、
色や座標の計算はしない。合成のためのオブジェクトと作業用の値は導入時の呼び出しの中に閉じ、
実行中は保持しない。ゲームの描画用ヒープの取り分は変わらない。

## 確認

PC試験は実入力または自作入力と、端点・細かい変化・8bitの中間値を含む6種類の
自作入力を各150位相で比較する。余白を含む1面2,048バイトを元の式と一致させる。
保存した150コマを0の面へ展開した結果も、同じ全入力・全150位相で元の式の2,048バイトと一致させる。
ARM向けの生成コードについても、実入力の全150位相をエミュレーションで照合する。
実機のGPU描画とCPU時間は別に確認し、開発版の状態表示で導入時の合成時間と、
毎フレームのコピー＋排出の現在・平均・最大の時間を読む。

GPUへ渡す面は書き込み後にCPUデータキャッシュを排出する。
帯の描画では前の板のバッチを流してから、テクスチャキャッシュを明示的に無効化する。
面の再利用は両画面の記録から非参照のPresentを8回数える既存の規則を保ち、10面を巡回する。
これはGXの提出世代と完了数を対応させるフェンスではない。

# 3D の共通部品

SceneResources は親ヒープの総量と連続した空きを確かめ、資源・instance の名前付きヒープを作る。
資源の見積もりは固定値、またはファイルの合計サイズ × 1.5 + 16 KiB。
モデルの型は SkeletalModel のみ、または Model と SkeletalModel の両方を選べる。
複数ファイルは順に読み、links に指定した組を Setup で結ぶ。

読み込みの回数は診断用に数える。上限で打ち切らない。
非表示・場面変更・持ち主の取り消しが来ても、現在読んでいる1本が完了するまで holder とヒープを保持する。
読み込み中止 API は呼ばない。instance → holder → ヒープの順で返す。
Shutdown は120回まで待つ。間に合わなければパス・holder・allocator を含む Session 全体を返さず保持し、
UnitCursor::Status().retained_on_shutdown に残す。

UnitCursor は持ち主を1つに限定し、表示希望と位置の並びをゲームのフレームで反映する。
1つの体を最大256か所に描き、ゲーム側のヒープは位置の数で増えない。
通常は親ヒープから64 KiBを借り、さらに48 KiBを残す。
描画の登録を外した後、4フレーム待って使用済みの資源を返す。
位置・行列・資源の記憶域・材質の退避は使用中だけ確保する。
常駐状態の予算は256 B、フレーム処理は最大14本。コールバック2欄は既存9本のコードフックとは別枠。

MaterialTint は View で材質の写しにも描画中の一時変更にも適用できる。
Push の後、指す領域を生かしたまま Restore を呼ぶ。
LUT が読めない場合は変更しない。半透明材質は元のブレンドと深度を維持し、TEV のアルファに掛ける。
全段使用で元のアルファを安全に残せない半透明材質は変更を断る。

FgobjDrawHook は層0の前・後と層1の前に配る。
Wire でコールバック関数の所有を予約し、導入時にも2欄を同時に照合する。
他者の値は上書きしない。順不同の解除では、自分のラッパーが欄へ戻るまで復元を保留する。
ラッパーの寿命はプラグイン全体と同じ。場面が変わった場合は古い欄へ書かない。
フレームの順序は world/frame_order.hpp に集める。

## 実機で確かめる手順

1. 村で開発版のカーソル項目を実行し、足元の3×3が別々の位置に描かれることを確認する。色変更後に表示を消す。
2. 表示要求直後と表示後のそれぞれで家へ入り、村へ戻って再表示する。別の場面への移行でも同じ操作を行う。
3. 建物の多い村や手紙の場面で親ヒープの空き不足を確認し、落ちずに待機し、空きが戻れば生成できることを確かめる。
4. 室内で表示要求し、描画ノードがなくても落ちないことを確かめる。
5. 同じコールバック欄を使う開発用の代役を後から入れ、逆順と順不同の両方で解除する。代役の値を壊さず、最後にゲームの値へ戻ることを確認する。
6. グロー・炎などの半透明材質の写しへ色を適用し、復元後の画像を適用前と比較する。深度と画素ごとのアルファが保たれることを確認する。

PC 試験は状態、代役のメモリ、所有者、コールバックの復元、行列キャッシュの更新を確認する。
実際の非同期 I/O、ゲームの ABI、GPU の見え方、資源を返すまでの4フレームの十分性は実機で確認する。

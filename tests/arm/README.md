# 帯の描画を元の ARM コードで試す

devkitARM、Python 3.11 以上、`unicorn`・`pyelftools` が必要です。
手元の対象版の未変更 `code.bin` を明示して実行します。ROM のコードや資源は収録しません。

```sh
python tests/arm/streaming_picture.py --code <手元のcode.bin> --cxx arm-none-eabi-g++ --report <作業場の結果.json>
```

ゲームコードの全体ハッシュと描画入口の照合値を確認した後、製品と同じ ARM 用の最適化で
帯コールバックをビルドし、ゲームの Picture・テクスチャ状態更新・バッチ流し出し・コピーを
代役なしで CPU 実行します。バッチが空の時、先行する板がある時、同じテクスチャ、
UV 数の変化、頂点色、満杯での送出、連続300枚を試します。

元の関数を順に呼んで作る参照記録とのバイト一致、既存記録の保持、前後の番兵、
書き込み先、カーソル、スタック復帰、記録ヘッダーの長さを検査します。
ELF は `build/arm/` に作ります。通常の PC 試験は ROM なしで実行できます。
`--plugin-elf out/gohan.elf` を付けると、実際に配布する製品 ELF 内のコールバックを実行します。
GPU の実行・実画素・実機の時間はこの試験では確かめられません。
